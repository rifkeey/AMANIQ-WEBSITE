How to use it. For a new site, read sections 1 to 3 once, then follow Playbook A (simple PHP sites like amaniqgroup.com) or Playbook B (the Laravel Academy) step by step, ticking the boxes. Finish with section 7. If anything fails, go to section 8.
Golden rules.
  1. Secrets (passwords, keys) live only in the server's settings file (config.php or .env). Never in GitHub, email or chat.
  2. Only the web folder (public_html) is public. Code, settings and logs sit beside it, never inside it.
  3. Never delete files on the server blindly. Download a copy, or move them to a backup folder first.
  4. After 2 failed logins (email, SMTP), stop and check. Repeated failures get you blocked.

Section 4

Playbook A: launch any simple PHP site

Use this for sites built like amaniqgroup.com: plain PHP, no database, a public_html folder and a private folder beside it. About 1 to 2 hours.

Phase 1: prepare on your PC

1

Make sure everything is saved and pushed

The upload is built from the last saved version in Git, so commit and push first.

2

Build the two upload ZIP files

In Git Bash, inside the project folder (replace amaniq with the private folder's name for other projects):

mkdir -p ../UPLOAD
git archive --format=zip -o ../UPLOAD/public_html.zip HEAD:public_html
git archive --format=zip --prefix=amaniq/ -o ../UPLOAD/amaniq.zip HEAD:amaniq

This automatically includes hidden files like .htaccess and leaves out your local settings file and test data.

3

Generate a security key

In PowerShell, then copy the 64-character result somewhere private for a few minutes:

& "C:\Users\IBRAHIM MOHAMMED\AppData\Local\Microsoft\WinGet\Packages\PHP.PHP.8.3_Microsoft.Winget.Source_8wekyb3d8bbwe\php.exe" -r "echo bin2hex(random_bytes(32));"

Phase 2: domain, SSL and email

4

Create the domain or subdomain

In Domain Setup (new domain) or Subdomain Management (e.g. labs.amaniqgroup.com). It appears as domains/<name>/public_html. A new domain bought elsewhere must have its nameservers set to GO54's (from your hosting welcome email); allow up to 48 hours.

5

Check SSL

SSL/TLS Certificates → Manage certificates. Any *.amaniqgroup.com subdomain is already covered by the wildcard. A brand-new domain needs its own certificate: request it there once the domain points to GO54.

6

Create the sending mailbox

In E-mail Accounts, create (or reuse) a private sending mailbox with a long password of letters and numbers only. Log in to webmail once with it to prove the password works.

Phase 3: upload

7

Clear the web folder safely

Open domains/<domain>/public_html. If anything is there (except cgi-bin or .well-known), download it, create old-site-backup one level up, and Move the files into it.

8

Upload and extract the website files

In public_html: Upload public_html.zip → select it → Extract (under More) → delete the ZIP.

9

Upload and extract the private folder

Go up to domains/<domain> (the folder that contains public_html, logs, stats). Upload amaniq.zip there, extract, delete the ZIP. Opening the site should now say "The website is being configured".

domains/<domain>/
├── amaniq/            private: code, content, settings, logs
├── public_html/       public: index.php, .htaccess, assets
├── old-site-backup/   anything that was there before
└── logs, stats, awstats, public_ftp   (created by GO54, leave alone)

Phase 4: settings, PHP and go

10

Create the settings file

In amaniq/config: select config.example.php → Duplicate → Rename the copy to config.php → Edit:

'env' => 'production',
'base_url' => 'https://amaniqgroup.com',      // this site's address
'force_https' => true,                        // once SSL is valid
'username' => 'contact@amaniqgroup.com',      // mail section
'password' => 'TheMailboxPasswordLettersAndNumbers',
'app_key' => 'THE-64-CHARACTER-KEY',          // security section

Remove any getenv(...) ?: part from the lines you edit. Keep the quotes and the comma. Save, then More → Permissions → 600.

11

Set the PHP version

Select PHP Version → PHP 8.3. Extensions: mbstring, openssl, curl on.

12

Open the site and run the launch-day checks

Reload the site, then work through Section 7. Save a private copy of the server's config.php (password manager or encrypted USB).

Section 5

Playbook B: launch academy.amaniqgroup.com (Laravel)

The Academy (D:\My PROJECTS\ACADEMY-laravel, GitHub rifkeey/ACADEMY-laravel) is a Laravel 13 app with a MySQL database, learner accounts and optional Paystack payments. It needs a few more steps than Playbook A. Allow half a day, and do it on a quiet day.

Good news already in place: the folder domains/academy.amaniqgroup.com exists, the wildcard SSL certificate covers the subdomain, and the academy@ mailbox exists.
The Academy repo's own docs/DEPLOYMENT_GO54.md was written for cPanel. Where it disagrees with this playbook about folders or menu names, follow this playbook.

Before you start: confirm with GO54 support

  • PHP 8.3 (or newer) is available in Select PHP Version, with: pdo_mysql, mbstring, intl, gd, fileinfo, openssl, zip, bcmath, curl, dom, xml, tokenizer, ctype
  • The database server version (MySQL 8 or MariaDB). phpMyAdmin shows it on its home page
  • Whether SSH/Terminal access can be enabled (makes setup and updates much easier)
  • Whether the website may connect out to api.paystack.co (only if you will take payments)
  • The full path of PHP 8.3 for cron jobs (on CloudLinux often /opt/alt/php83/usr/bin/php; confirm)

Phase 1: prepare the release on your PC

1

Install production dependencies

In the ACADEMY-laravel folder:

composer install --no-dev --optimize-autoloader
php artisan test          # optional, needs the local test database

Compiled CSS/JS (public/build) is already saved in Git, so Node.js is not needed on the server.

2

Make two ZIP files

academy-app.zip: the whole project folder except .env, node_modules, tests, .git and the contents of storage/logs. It must include vendor/.
academy-public.zip: the contents of the public folder, including .htaccess.

Ask Claude to build both ZIP files; it can do this reliably and check what is inside.

Phase 2: folders on the server

GO54 serves the subdomain from domains/academy.amaniqgroup.com/public_html. Laravel expects to be served from its own public folder. We use the same pattern as the main site: public files in public_html, the application beside it.

domains/academy.amaniqgroup.com/
├── academy/          the Laravel app: app, bootstrap, config, vendor, storage, .env
└── public_html/      contents of Laravel's public/ folder, with an edited index.php
3

Upload

Clear public_html safely (Playbook A step 7). Upload academy-public.zip into public_html and extract. Upload academy-app.zip into domains/academy.amaniqgroup.com and extract so the app is in a folder named academy.

4

Point public_html/index.php at the app

Edit public_html/index.php so it reads exactly:

<?php

use Illuminate\Foundation\Application;
use Illuminate\Http\Request;

define('LARAVEL_START', microtime(true));

$appDir = __DIR__.'/../academy';   // the app sits beside public_html

if (file_exists($maintenance = $appDir.'/storage/framework/maintenance.php')) {
    require $maintenance;
}

require $appDir.'/vendor/autoload.php';

/** @var Application $app */
$app = require_once $appDir.'/bootstrap/app.php';
$app->usePublicPath(__DIR__);      // so CSS/JS and images load from public_html

$app->handleRequest(Request::capture());

Alternative: ask GO54 support to set the subdomain's document root to academy/public. Then you upload only the app and skip this edit.

Phase 3: database

5

Create the database

MySQL Management → Create new database. Name it e.g. academy (it becomes amaniqgr_academy), with a user and a long letters-and-numbers password. Note the full database name, user name and password.

Phase 4: the .env settings file

6

Create academy/.env from .env.example

Duplicate .env.example, rename the copy to .env, edit:

APP_ENV=production
APP_DEBUG=false
APP_KEY=base64:...                  # from: php artisan key:generate --show (on your PC)
APP_URL=https://academy.amaniqgroup.com
ACADEMY_SITE_URL=https://academy.amaniqgroup.com
DB_HOST=localhost
DB_DATABASE=amaniqgr_academy
DB_USERNAME=amaniqgr_academy
DB_PASSWORD=TheDatabasePassword
MAIL_HOST=mail.amaniqgroup.com
MAIL_PORT=465
MAIL_SCHEME=smtps
MAIL_USERNAME=academy@amaniqgroup.com
MAIL_PASSWORD=TheAcademyMailboxPassword
MAIL_FROM_ADDRESS="academy@amaniqgroup.com"
PAYMENT_PROVIDER=none               # or paystack with a live sk_live_ key

Permissions: .env → 600. Folders academy/storage and academy/bootstrap/cache → 775.

Phase 5: create the tables and content

7

With SSH (if GO54 enables it)

cd ~/domains/academy.amaniqgroup.com/academy
php -v                                       # must say 8.3; otherwise use the full path
php artisan migrate --force
php artisan db:seed --class=CatalogueSeeder --force
php artisan config:cache && php artisan route:cache && php artisan view:cache
8

Without SSH

In Cron Jobs, add a one-off job set to run every minute, with the command below. Wait two minutes, check academy/storage/logs, then delete the job. Repeat with db:seed --class=CatalogueSeeder --force.

cd /home/amaniqgr/domains/academy.amaniqgroup.com/academy && /opt/alt/php83/usr/bin/php artisan migrate --force

Avoid importing a database dump from your PC if GO54 runs MariaDB: MySQL 8 dumps can use collations MariaDB rejects. Running the migrations on the server avoids this.

Phase 6: first administrator and scheduler

9

Create your admin account

Register normally on https://academy.amaniqgroup.com. In phpMyAdmin, run UPDATE users SET role='admin' WHERE email='your@email'; Sign in, open Account → Security and turn on two-factor authentication. The admin area stays locked until you do. Never run DevAccountsSeeder on the server.

10

Add the scheduler cron job (every minute, permanent)

cd /home/amaniqgr/domains/academy.amaniqgroup.com/academy && /opt/alt/php83/usr/bin/php artisan schedule:run >> /dev/null 2>&1

Phase 7: payments and the main site link

11

Paystack (only when ready to sell)

Set PAYMENT_PROVIDER=paystack and the live secret key in .env. In the Paystack dashboard: webhook URL https://academy.amaniqgroup.com/webhooks/payments, callback https://academy.amaniqgroup.com/checkout/complete. Make one real low-value purchase and refund it. This has never been tested against the live API.

12

Switch the main site's Academy tab to the live platform

On the server, edit domains/amaniqgroup.com/amaniq/config/config.php and set 'academy' => ['url' => 'https://academy.amaniqgroup.com', 'live' => true],. The "Coming soon" page then sends visitors straight to the Academy.

Everything is sent from contact@. Pressing Reply goes to the person who wrote in. The routing is in the server's config.php under mail → routing and copy_to. The form allows 5 enquiries per visitor per 15 minutes.

Website mail settings that work on GO54

'transport'  => 'smtp',

'port'       => 465,
'encryption' => 'ssl',
'peer_name'  => 'mail.amaniqgroup.com',    // keeps the certificate check working with 127.0.0.1
'username'   => 'contact@amaniqgroup.com',
'password'   => '...letters and numbers...',

Setting up a mailbox on a phone or computer

  1. iPhone: Settings → Apps → Mail → Mail Accounts → Add Account → Other → Add Mail Account → choose IMAP.
  2. Incoming and outgoing host mail.amaniqgroup.com; user name is the full address; enter the password for outgoing too, even though iOS says "optional".
  3. If it saves but will not sync: incoming Advanced → SSL on, port 993; outgoing SMTP server → SSL on, port 465, Authentication: Password.
  4. Good apps: Apple Mail, Microsoft Outlook (phone and PC), Mozilla Thunderbird (free, PC), or webmail in any browser.
  5. Add info@ everywhere you want to see enquiries. Do not add contact@ to personal devices.

Email deliverability

In the panel's email section, make sure SPF and DKIM records exist for the domain, so enquiries and Academy emails do not land in spam. If a test email lands in spam, check these first.

Section 7

Launch-day checks

In a browser (5 minutes)

  • The home page loads with a padlock; click through every menu item, on a computer and on a phone
  • http:// and www. versions redirect to https:// without www
  • A made-up page (e.g. /test-404/) shows the branded "not found" page
  • /amaniq/config/config.php (or /.env for the Academy) shows Forbidden or Not Found, never the file
  • /sitemap.xml and /robots.txt load
  • Paste the address into LinkedIn's Post Inspector to check the sharing preview

Email (15 to 30 minutes)

  • One test enquiry per enquiry type arrives in the right inbox, with the copy in info@
  • Reply to one: it addresses the person who wrote in, not contact@
  • For the Academy: registration and password-reset emails arrive

From the PC (optional, automatic)

Ask Claude to "run the live checks against the site". For amaniqgroup.com that is 48 read-only checks: pages, redirects, security headers, blocked files and SEO files. Nothing is submitted.

After launch

  • Google Search Console: add the site and submit /sitemap.xml
  • Google Business Profile: same name, address and phone number as the website
  • Save a private copy of the server's settings file (config.php or .env)
  • Commit and push any last changes, so GitHub matches what is live

Section 9

Updating a live site safely

Main site (amaniqgroup.com)

  1. Make the change on your PC and test it at http://127.0.0.1:8080.
  2. Run the smoke test: php tools/smoke-test.php http://127.0.0.1:8080 (53 checks).
  3. Commit and push to GitHub.
  4. Upload only the changed files to the same place on the server. Never upload your local config.php.
  5. If you changed site.css, run php tools/build-assets.php first and upload site.min.css too.

Academy

  1. Turn on maintenance mode (SSH: php artisan down).
  2. Upload the changed files; upload vendor/ again if dependencies changed.
  3. Run php artisan migrate --force, then php artisan optimize:clear and the three cache commands.
  4. Turn maintenance mode off (php artisan up) and test sign-in.

Routine care

  • Monthly: send one test enquiry; skim the logs for repeated errors.
  • Quarterly: confirm the PHP version is still supported; check SSL renewal in the panel.
  • Yearly: review the Privacy Policy and Terms; update their "last updated" dates if changed.
